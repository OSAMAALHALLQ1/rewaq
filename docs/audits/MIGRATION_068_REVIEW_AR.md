# مراجعة ترحيل 068 — أكواد الموظفين وتوجيه وجبات المطعم

## الهدف

يربط هذا الترحيل الوجبة بقسم التحضير، ويفصل KDS لكل قسم عن Expo، ويدعم جهاز المحاسب المركزي، وتعديل أسماء أقسام التشغيل، وعرض كود الموظف للمالك بعد تشفيره على الخادم.

## التغييرات

- إضافة `team_invites.employee_code_ciphertext` لتخزين كود الموظف بتشفير AES-256-GCM. بصمة SHA-256 الحالية تبقى هي مصدر التحقق عند تسجيل الدخول.
- إضافة `catalog_item_kitchen_routes` لربط الصنف بقسم تحضير واحد لكل نطاق تشغيل.
- إضافة RPC مدقق ومؤرشف لتوجيه الوجبات، وتعديل أسماء أقسام التشغيل، وإنشاء أجهزة دورة المطعم.
- جعل KDS يحتاج قسم تحضير صريحاً؛ النادل وExpo يعملان على نطاق التشغيل دون ربطهما بمحطة واحدة.
- السماح لجهاز المحاسب المركزي فقط بأن يكون بلا نطاق تشغيل.

## ضوابط الأمان والنزاهة

- لا يحذف الترحيل أي موظف أو جهاز أو طلب أو فاتورة أو حركة مخزون أو سجل تدقيق.
- حذف مسارات الوجبات محظور؛ التصحيح يتم بالتحديث أو التعطيل مع سجل تدقيق.
- كل RPC إداري يتحقق من المؤسسة والدور ونطاق التشغيل.
- كود الموظف الخام لا يدخل سجل التدقيق، ومفتاح التشفير لا يدخل PostgreSQL أو Git.
- الكاشير لا يستطيع فوترة طلب المطعم قبل اكتمال التحضير، ولا يستطيع تغيير الأصناف ثم ربط الفاتورة بالطلب.

## المخاطر وخطة الحد منها

- الأكواد القديمة لا يمكن استعادتها من بصمة SHA-256؛ يصدر المالك كوداً جديداً مرة واحدة لتعبئة النص المشفر.
- الوجبات القديمة لا توجه تلقائياً قبل ربطها بقسم؛ واجهة النادل تعطلها بوضوح حتى يربطها المالك.
- نشر التطبيق قبل الترحيل سيجعل استعلامات المسارات تفشل؛ ترتيب النشر الإلزامي هو: سر التشفير، ثم migration 068، ثم التطبيق.
- تغيير اسم القسم لا يغيّر المعرّف، لذلك تبقى الأجهزة والطلبات والفواتير والمخزون مرتبطة دون انقطاع.

## تحقق ما بعد التطبيق

```sql
select id, full_name, employee_code_ciphertext is not null as owner_can_recover
from public.team_invites
order by created_at desc;

select route.branch_id, item.name as item_name, station.name as station_name, route.is_active
from public.catalog_item_kitchen_routes route
join public.catalog_items item on item.id = route.catalog_item_id
join public.kitchen_stations station on station.id = route.station_id
order by route.updated_at desc;

select action, entity_type, entity_id, created_at
from public.audit_logs
where action in (
  'branch_created', 'branch_updated',
  'catalog_item_kitchen_route_upserted',
  'restaurant_workflow_device_provisioned',
  'restaurant_order_invoice_linked'
)
order by created_at desc;
```

## التصحيح الأمامي

- مسار وجبة خاطئ: أعد ربط الوجبة بالقسم الصحيح؛ لا تحذف السجل.
- جهاز خاطئ: عطله من واجهة الأجهزة وأنشئ بديلاً؛ لا تحذف سجل الجهاز أو التدقيق.
- كود موظف قديم أو غير قابل للعرض: استخدم «إصدار كود قابل للعرض» لإلغاء القديم وإصدار كود مشفر جديد.
- لا يوجد rollback يحذف بيانات تشغيلية. عند الحاجة يعطل التطبيق استخدام الوظيفة الجديدة، وتبقى الجداول والسجلات محفوظة حتى تصحيح أمامي لاحق.
